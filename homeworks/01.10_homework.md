## 1. Базовые команды управления транзакциями и уровни изоляции
```sql
BEGIN TRANSACTION; -- Начало
COMMIT; -- Успешная фиксация (изменения становятся постоянными)
ROLLBACK; -- Откат (отмена всех изменений)
SET IMPLICIT_TRANSACTIONS ON; -- Включение неявных транзакций
```
**Что происходит?**
> * Транзакция — это логическая единица работы, переводящая базу данных из одного согласованного состояния в другое.
> * Если включить IMPLICIT_TRANSACTIONS ON, новая транзакция начинается неявно после завершения предыдущей, но требует явного COMMIT или ROLLBACK.
> * По умолчанию в SQL Server работает автофиксация: каждая инструкция фиксируется сразу после завершения.

**Установка уровня изоляции:**
```sql
SET TRANSACTION ISOLATION LEVEL 
    { READ UNCOMMITTED | READ COMMITTED | REPEATABLE READ | SNAPSHOT | SERIALIZABLE };
```
> * READ UNCOMMITTED: Наименьшее ограничение, не устанавливает блокировки на чтение, позволяет читать незафиксированные («грязные») данные.
> * READ COMMITTED: Установлен в SQL Server по умолчанию, запрещает чтение грязных данных.
> * REPEATABLE READ: Совмещаемые блокировки сохраняются до завершения транзакции, запрещая другим изменять считанные строки, но новые строки (фантомы) могут появляться.
> * SERIALIZABLE: Наивысший уровень, предотвращающий появление фантомных строк путем блокировки всего считанного диапазона ключей.
> * SNAPSHOT: Требует настройки ALLOW_SNAPSHOT_ISOLATION ON и использует версии строк в tempdb вместо блокировок, снижая вероятность тупиков.

## 2. Вложенные транзакции
```sql
CREATE TABLE tbl(id int identity,field varchar(50))
DECLARE @i bit
BEGIN TRAN
  INSERT tbl(field) SELECT 'test1'
  SELECT @i=1 --or 0
  BEGIN TRAN
    INSERT tbl(field) SELECT 'test2'
    IF @i=1 ROLLBACK TRAN ELSE COMMIT TRAN
  INSERT tbl(field) SELECT 'test3'
COMMIT TRAN
SELECT * FROM tbl
DROP TABLE tbl
```

**Что происходит?**
> * Фиксация внутренних транзакций через COMMIT не освобождает ресурсы и не делает изменения постоянными — она лишь уменьшает системный счетчик @@TRANCOUNT на 1.
> * Изменения фиксируются только при фиксации самой внешней транзакции (когда @@TRANCOUNT становится равным нулю).
> * Откат (ROLLBACK) любой вложенной транзакции автоматически откатывает все внешние транзакции.

## 3. Точки сохранения
```sql
CREATE TABLE ValueTable ([value] int)
BEGIN TRAN
       INSERT INTO ValueTable VALUES(1)
BEGIN TRAN
       INSERT INTO ValueTable VALUES(2)
SAVE TRAN SavePoint1
BEGIN TRAN
       INSERT INTO ValueTable VALUES(3)
ROLLBACK TRAN SavePoint1
INSERT INTO ValueTable VALUES(4)
SELECT * FROM ValueTable
DROP TABLE ValueTable
```
**Что происходит**
> * SAVE TRAN SavePoint1 устанавливает точку сохранения.
> * Команда ROLLBACK TRAN SavePoint1 отменяет только ту работу, которая была выполнена после создания точки сохранения (в данном случае отменится вставка значения 3).
> * В отличие от полного отката, ROLLBACK до точки сохранения не уменьшает счетчик @@TRANCOUNT и транзакция остается активной.

## 4. Обработка ошибок
```sql
CREATE TABLE table1 (i int NOT NULL PRIMARY KEY, col1 varchar(20) NOT NULL, col2 varchar(20) NULL);

SET XACT_ABORT ON; -- Управление откатом

BEGIN TRY
  BEGIN TRAN
  INSERT INTO table1 (i,col1,col2) VALUES (1,'First row','First row'); 
  -- Вставка с ошибкой (если есть нарушение ограничений)
  INSERT INTO table1 (i,col1,col2) VALUES (2,NULL,'Second row'); 
  INSERT INTO table1 (i,col1,col2) VALUES (3,'Third row','Third row'); 
  COMMIT TRAN; 
END TRY 
BEGIN CATCH 
  ROLLBACK TRAN; 
END CATCH;

SELECT XACT_STATE();
```
**Что происходит?**
> * При SET XACT_ABORT ON любая ошибка немедленно обрывает всю транзакцию целиком и выполняет полный откат. При значении OFF (по умолчанию) в некоторых случаях откатывается только ошибочная инструкция, а транзакция продолжается.
> * Блок TRY...CATCH перехватывает сбой и передает управление в CATCH, где можно безопасно вызвать ROLLBACK и запросить функцию @@error.
> * Функция XACT_STATE() возвращает статус транзакции: 1 (активна и может быть зафиксирована), 0 (нет активной транзакции) или -1 (произошла ошибка, транзакция "мертва" и подлежит только полному откату).

## 5. Управление журналом транзакций
```sql
DBCC SHRINKFILE (DataFile1, 7);
```
**Что это?**
> * Процесс "усечения" (truncation) происходит автоматически: он помечает виртуальные файлы журнала (VLF) как неактивные, освобождая место внутри самого файла, но физический размер файла на диске от этого не уменьшается.
> * Для реального уменьшения размера файла журнала (освобождения дискового пространства) применяется команда DBCC SHRINKFILE, где указывается логическое имя файла и желаемый размер в мегабайтах.
