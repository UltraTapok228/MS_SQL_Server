# Лабораторная работа. Транзакции (BEGIN/COMMIT/ROLLBACK, TRY/CATCH, XACT_ABORT, SAVE TRANSACTION)

Практические задания по транзакциям, обработке ошибок и вложенным транзакциям.

---

## Задание 1. Основы транзакций

### Что требовалось
Создать таблицу Accounts с полями AccountId, OwnerName, Balance. Наполнить тремя счетами. Написать успешную транзакцию (перевод 1000 руб.) и транзакцию с ошибкой → ROLLBACK. Объяснить, почему откат сработал.

### Что сделано
Создана таблица Accounts с ограничением CHECK (Balance >= 0), чтобы при нехватке средств возникала ошибка. Добавлены три счёта: 5000, 3000, 10000.

Скрипт 1 — успешный перевод: списание 1000 со счёта 1, зачисление 1000 на счёт 2, COMMIT.

Скрипт 2 — транзакция с ошибкой: успешное списание 1000 со счёта 3, затем списание 99999 со счёта 2 (нарушение CHECK), после чего выполняется ROLLBACK.

```sql
-- 1. Создание таблицы и наполнение данными
CREATE TABLE Accounts (
    AccountId INT PRIMARY KEY,
    OwnerName NVARCHAR(100),
    -- Добавляем CHECK для генерации ошибки при нехватке средств
    Balance DECIMAL(18, 2) CHECK (Balance >= 0) 
);

INSERT INTO Accounts VALUES
(1, 'Иванов', 5000.00),
(2, 'Петров', 3000.00),
(3, 'Сидоров', 10000.00);
GO

-- 2. Скрипт 1: Успешный перевод (COMMIT)
BEGIN TRANSACTION;
    -- Снимаем 1000 со счета 1
    UPDATE Accounts SET Balance = Balance - 1000 WHERE AccountId = 1;
    -- Зачисляем 1000 на счет 2
    UPDATE Accounts SET Balance = Balance + 1000 WHERE AccountId = 2;
COMMIT TRANSACTION;
GO

-- 3. Скрипт 2: Транзакция с ошибкой (ROLLBACK)
BEGIN TRANSACTION;
    -- Успешное снятие
    UPDATE Accounts SET Balance = Balance - 1000 WHERE AccountId = 3;
    
    -- Ошибка: попытка снять сумму, превышающую баланс (нарушение CHECK)
    UPDATE Accounts SET Balance = Balance - 99999 WHERE AccountId = 2;
    
-- Откатываем обе операции
ROLLBACK TRANSACTION;
GO
```

### Анализ
Транзакция — логическая единица работы, обладающая свойством атомарности: выполняются либо все действия, либо ни одного. При вызове ROLLBACK система отменяет все изменения, сделанные в рамках транзакции, и возвращает данные к состоянию, которое было до BEGIN TRANSACTION. Поэтому откатилось и первое, успешное списание.

### Вывод
Транзакции обеспечивают атомарность: при ошибке в любой операции база возвращается к согласованному состоянию.

## Задание 2. Обработка ошибок с TRY...CATCH и XACT_ABORT

### Что требовалось
Реализовать перевод денег внутри TRY...CATCH. В CATCH — ROLLBACK, вывод ERROR_NUMBER() и ERROR_MESSAGE(). Протестировать поведение с XACT_ABORT ON и OFF. Описать разницу.

### Что сделано
Перевод помещён в блок TRY. Ошибка вызвана искусственно — делением на ноль между двумя UPDATE. В блоке CATCH проверяется @@TRANCOUNT, при необходимости выполняется ROLLBACK, затем выводятся ERROR_NUMBER() и ERROR_MESSAGE(). Скрипт выполняется сначала с XACT_ABORT ON, затем с OFF.

```sql
-- Попробуй выполнить скрипт сначала с ON, а затем с OFF
SET XACT_ABORT ON; 

BEGIN TRY
    BEGIN TRANSACTION;
        UPDATE Accounts SET Balance = Balance - 1000 WHERE AccountId = 1;
        
        -- Искусственная ошибка: деление на ноль
        DECLARE @Error INT = 1 / 0; 
        
        UPDATE Accounts SET Balance = Balance + 1000 WHERE AccountId = 2;
    COMMIT TRANSACTION;
END TRY
BEGIN CATCH
    -- Проверяем, есть ли открытая транзакция перед откатом
    IF @@TRANCOUNT > 0
        ROLLBACK TRANSACTION;

    -- Вывод системной информации об ошибке
    SELECT 
        ERROR_NUMBER() AS ErrorNum, 
        ERROR_MESSAGE() AS ErrorMsg;
END CATCH;
GO
```

### Анализ
- XACT_ABORT ON: при ошибке T-SQL вся транзакция автоматически завершается и немедленно откатывается целиком.
- XACT_ABORT OFF (по умолчанию): в некоторых случаях откатывается только инструкция, вызвавшая сбой, а транзакция остаётся открытой и продолжает работу.
- Проверка IF @@TRANCOUNT > 0 перед ROLLBACK безопасна в обоих режимах.

### Вывод
Для критичных операций (финансовых) рекомендуется XACT_ABORT ON — он гарантирует атомарность.

## Задание 3. Вложенные транзакции и SAVE TRANSACTION

### Что требовалось
Смоделировать три операции в одной транзакции: списание со счёта A, зачисление на счёт B, запись в TransferLog. Использовать SAVE TRANSACTION SavePoint1 после шага 1. При ошибке на шаге 3 — откат только к SavePoint1. Вопрос: почему ROLLBACK SavePoint1 не уменьшает @@TRANCOUNT?

### Что сделано
Создана таблица TransferLog. В транзакции выполнено списание со счёта 1, затем установлена точка сохранения SavePoint1, после чего выполнено зачисление на счёт 2. Шаг 3 (запись в лог) оставлен в виде комментария — вместо него выполнен откат к SavePoint1, после чего транзакция зафиксирована. В итоге сохраняется только шаг 1.

```sql
CREATE TABLE TransferLog (LogId INT IDENTITY, LogMsg NVARCHAR(100));
GO

BEGIN TRANSACTION;
    -- 1: Списание
    UPDATE Accounts SET Balance = Balance - 1000 WHERE AccountId = 1;

    -- Сохраняем состояние после успешного Шага 1
    SAVE TRANSACTION SavePoint1;

    -- 2: Зачисление
    UPDATE Accounts SET Balance = Balance + 1000 WHERE AccountId = 2;

    -- 3: Запись в лог
    -- если запист не удалась, то отменяем шаг 2, и сохраняем шаг 1
    ROLLBACK TRANSACTION SavePoint1;

-- фиксация транзакии, запишется только шаг 1
COMMIT TRANSACTION;
GO
```

### Результат
Шаг 1 сохранён, шаг 2 отменён откатом к SavePoint1.

### Анализ
@@TRANCOUNT отслеживает общее количество открытых транзакций. Откат к точке сохранения отменяет лишь часть операций внутри текущей активной транзакции, но не закрывает саму транзакцию. Она остаётся открытой и требует финального COMMIT или полного ROLLBACK.

### Ответ на вопрос
ROLLBACK TRANSACTION SavePoint1 не уменьшает @@TRANCOUNT, потому что SAVE TRANSACTION не создаёт новую транзакцию — это лишь метка внутри текущей. Транзакция физически остаётся открытой, поэтому счётчик не меняется.

### Вывод
SAVE TRANSACTION удобен для частичного отката внутри большой транзакции.
