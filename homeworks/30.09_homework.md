## Задание 1. Триггеры для таблицы

### Что требовалось
Создать для таблицы Students триггеры на INSERT, UPDATE и DELETE. Спровоцировать срабатывание каждого из них и показать результат.

### Что сделано
Созданы три триггера на таблицу Students:

- trg_AfterInsert_Student (AFTER INSERT) — выводит сообщение с именем добавленного студента.
- trg_AfterUpdate_Student (AFTER UPDATE) — если изменён GroupId, сообщает о переводе в другую группу, иначе о обычном обновлении данных.
- trg_PreventDelete_Student (INSTEAD OF DELETE) — запрещает удаление, вместо него выводит сообщение об ошибке.

```sql
USE College2;
GO

-- 1 Триггер вида INSERT (срабатывает после добавления нового студента)
CREATE OR ALTER TRIGGER trg_AfterInsert_Student
ON Students
AFTER INSERT
AS
BEGIN
    DECLARE @NewName NVARCHAR(100);
    SELECT @NewName = FullName FROM inserted;
    
    PRINT 'Успех! В систему добавлен новый студент: ' + @NewName;
END;
GO

-- 2 Триггер вида UPDATE
CREATE OR ALTER TRIGGER trg_AfterUpdate_Student
ON Students
AFTER UPDATE
AS
BEGIN
    IF UPDATE(GroupId)
    BEGIN
        PRINT 'Внимание: Зафиксирован перевод студента в другую группу!';
    END
    ELSE
    BEGIN
        PRINT 'Данные студента были обновлены.';
    END
END;
GO

-- 3 Триггер вида DELETE
CREATE OR ALTER TRIGGER trg_PreventDelete_Student
ON Students
INSTEAD OF DELETE
AS
BEGIN
    PRINT 'ОШИБКА: Удаление записей из таблицы Students запрещено политикой безопасности!';
END;
GO
```

Для проверки триггеры спровоцированы: добавлен тестовый студент, переведён в группу 2, затем сделана попытка удаления.

```sql
USE College2;
GO

-- 1 Провоцируем триггер INSERT (добавляем тестового студента)
INSERT INTO Students (FullName, GroupId, EnrolledYear) 
VALUES ('Тестов Тест Тестович', 1, 2026);

-- 2 Провоцируем триггер UPDATE (переводим его в группу 2)
UPDATE Students 
SET GroupId = 2 
WHERE FullName = 'Тестов Тест Тестович';

-- 3 Провоцируем триггер DELETE (пытаемся его удалить - триггер должен это запретить)
DELETE FROM Students 
WHERE FullName = 'Тестов Тест Тестович';
```

### Анализ
- AFTER-триггеры срабатывают после выполнения операции и читают изменённые строки из псевдотаблицы inserted.
- Функция UPDATE(GroupId) позволяет определить, затронут ли конкретный столбец.
- INSTEAD OF DELETE подменяет само удаление: записи остаются в таблице, так как внутри триггера DELETE не выполняется.

### Вывод
DML-триггеры позволяют реагировать на изменения данных и защищать таблицу от нежелательных операций.

## Задание 2. Триггеры для базы данных

### Что требовалось
Создать триггеры уровня базы данных на создание и удаление таблиц. Спровоцировать их срабатывание.

### Что сделано
Созданы два DDL-триггера на уровне базы College2:

- trg_DB_CreateTable (FOR CREATE_TABLE) — логирование: выводит уведомление при каждом создании таблицы.
- trg_DB_PreventDropTable (FOR DROP_TABLE) — защита: выводит сообщение и выполняет ROLLBACK, не давая удалить таблицу.

```sql
USE College2;
GO

-- 1 Триггер БД на создание новых таблиц (Логирование)
CREATE OR ALTER TRIGGER trg_DB_CreateTable
ON DATABASE
FOR CREATE_TABLE
AS
BEGIN
    -- вывод уведомления каждый раз, когда кто-то пишет CREATE TABLE
    PRINT 'Событие БД: В базе данных College2 была создана новая таблица!';
END;
GO

-- 2. Триггер БД на удаление таблиц (Защита)
CREATE OR ALTER TRIGGER trg_DB_PreventDropTable
ON DATABASE
FOR DROP_TABLE
AS
BEGIN
    PRINT 'КРИТИЧЕСКАЯ ОШИБКА: Удаление таблиц в этой базе запрещено!';
    -- Откатываем транзакцию, не давая удалить таблицу
    ROLLBACK; 
END;
GO
```

Для проверки создана тестовая таблица и сделана попытка её удалить:

```sql
USE College2;
GO

-- 1 провокация триггера CREATE_TABLE
CREATE TABLE TestTriggerTable (
    Id INT PRIMARY KEY
);

-- 2 провокация триггера DROP_TABLE (попытка удалить эту табличку - триггер откатит действие)
DROP TABLE TestTriggerTable;
```

### Анализ
- DDL-триггеры срабатывают на события определения данных (CREATE_TABLE, DROP_TABLE), а не на изменение строк.
- Команда DROP TABLE выполняется внутри неявной транзакции, поэтому ROLLBACK в триггере отменяет удаление.
- Тестовая таблица TestTriggerTable после попытки удаления остаётся в базе.

### Вывод
DDL-триггеры подходят для аудита изменений схемы и защиты базы от случайного удаления таблиц.

## Общий вывод

| Задание | Что показал |
|---|---|
| 1 | DML-триггеры: AFTER INSERT, AFTER UPDATE, INSTEAD OF DELETE |
| 2 | DDL-триггеры на уровне базы: CREATE_TABLE, DROP_TABLE |

**Ключевые принципы:**
1. AFTER-триггер выполняется после операции, INSTEAD OF — вместо неё.
2. Псевдотаблицы inserted и deleted содержат затронутые строки.
3. UPDATE(столбец) проверяет, менялся ли конкретный столбец.
4. DDL-триггеры (ON DATABASE) позволяют логировать и блокировать изменения схемы.
5. ROLLBACK в триггере отменяет вызвавшую его операцию.
