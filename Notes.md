**Архитектура MS SQL Server** 
* Microsoft SQL Server — это корпоративная реляционная СУБД, построенная по клиент-серверной архитектуре. 
* Клиент отправляет запрос на языке T-SQL, а сервер принимает обращение и выполняет поставленную задачу, возвращая результат. 
* База данных состоит из двух файлов: самого файла данных и журнала транзакций (рабочая область, куда записывается информация до и после выполнения каждой транзакции). 

**Создание БД** 
В состав БД входят: 
* **Таблицы**: хранят собственно данные. 
* **Представления (Views)**: выражения языка SQL, которые возвращают набор данных в виде таблицы.  В обозревателе объектов они хранятся в отдельной папке и используются в том числе для создания статических запросов. 
* **Хранимые процедуры**: выполняют код на языке SQL по отношению к данным к БД (например, получает данные или изменяет их). 
* **BLOB-поля**: данные в формате больших двоичных данных. 
* **Иные метаданные**. 

**Системные БД**   
Эти базы можно увидеть через SQL Server Management Studio в узле Databases -> System Databases: 
* **master**: главная база данных сервера, хранит все используемые логины пользователей сервера, их роли, различные конфигурационные настройки, имена и информацию о базах данных. 
* **model**: база данных представляет шаблон, на основе которого создаются другие базы данных. 
* **msdb**: хранит информацию о работе планировщика SQL, а также информацию о бекапах баз данных. 
* **tempdb**: используется как хранилище для временных объектов и заново пересоздается при каждом запуске сервера. 

**Какие есть типы данных:**   
* **Целочисленные типы данных (хранятся числа)**: 
  - Tinyint: от 0 до 255 (занимает 1 байт). 
  - Smallint: от –32 768 до 32 767 (занимает 2 байта). 
  - Int: от –2 147 483 648 до 2 147 483 647 (занимает 4 байта). 
  - Bigint: очень большие числа (занимает 8 байт). 

* **Типы данных для хранения дробных чисел**:   
  - Real, Float. 
  - Decimal: хранит числа c фиксированной точностью (от 5 до 17 байт в зависимости от количества чисел после запятой). 

* **Битовые (логические) типы данных**: 
  - Bit: хранит значение 0 или 1, фактически аналог булевого типа (занимает 1 байт). 

* **Типы данных даты и времени**:   
  - Datetime, SmallDatetime. 

* **Денежные типы данных для хранения финансовой информации**:   
  - Money, Smallmoney. 

* **Символьные (строковые) типы**:   
  - Char(n): строка фиксированной длины (выделяет по 1 байту на символ, не Unicode). 
  - Varchar(n): строка переменной длины (выделяется 1 байт на символ, не Unicode). 
  - Nchar(n) / Nvarchar(n): хранит строку в кодировке Unicode (выделяется 2 байта на каждый символ). 

* **Специальные типы данных**: 
  - Text, Image (до 2 Гб рисунков), RowGUID (уникальный идентификатор строки), SQL_Variant. 

**Основные команды T-SQL и работа в SSMS** 
* **Создание базы данных**: выполняется командой `CREATE DATABASE название_бд`.  В графическом интерфейсе это делается через правый клик по узлу Databases -> New Database. 
* **Удаление базы данных**: применяется команда `DROP DATABASE название_бд`. 
* **Прикрепление существующей БД (.mdf файла)**: выполняется командой `CREATE DATABASE имя_бд ON PRIMARY(FILENAME='путь_к_файлу_mdf') FOR ATTACH;`. 
* **Создание таблиц**: команда `CREATE TABLE название_таблицы (...)` с перечислением столбцов и их типов. 
* **Дизайнер таблиц в SSMS**: при создании через интерфейс содержит три колонки: Column Name (имя), Data Type (тип) и Allow Nulls (может ли быть пустым). 
* **Установка первичного ключа**: правый клик по столбцу -> Set Primary Key (появляется иконка "золотой ключ"). 
* **Создание автосчетчика (identity)**: в свойствах столбца нужно развернуть пункт "Спецификация идентификатора", установить значение "Да" и задать начальное значение и шаг приращения (обычно 1). 
* **Выполнение запросов**: для создания нового запроса нужно нажать New Query, а для выполнения написанного кода — кнопку Execute или клавишу F5.  Для извлечения данных из таблиц используется команда `SELECT`.

**Продвинутое создание БД (через код T-SQL)** 

База данных может создаваться с тонкой настройкой физических файлов.  В скрипте можно определить: 
* **.mdf** — основной файл данных (Primary). 
* **.ndf** — вторичные файлы данных (дополнительные). 
* **.ldf** — файл журнала транзакций (Log). 
* **FILEGROUP** — файловые группы (позволяют логически объединять файлы, например, `FG1`). 

Пример скрипта с настройкой файлов: 
```sql
CREATE DATABASE BSTU 
ON PRIMARY (
    NAME = N'BSTU_1', 
    FILENAME = N'D:\BD\BSTU_1.mdf', 
    SIZE = 10240Kb, 
    MAXSIZE = UNLIMITED, 
    FILEGROWTH = 1024Kb
), 
(
    NAME = N'BSTU_2', 
    FILENAME = N'D:\BD\BSTU_2.ndf', 
    SIZE = 10240KB, 
    MAXSIZE = 1Gb, 
    FILEGROWTH = 25%
), 
FILEGROUP FG1 (
    NAME = N'BSTU_fg1_1', 
    FILENAME = N'D:\BD\BSTU_3.ndf', 
    SIZE = 10240Kb, 
    MAXSIZE = 1Gb, 
    FILEGROWTH = 25%
), 
(
    NAME = N'BSTU_fg1_2', 
    FILENAME = N'D:\BD\BSTU_4.ndf', 
    SIZE = 10240Kb, 
    MAXSIZE = 1Gb, 
    FILEGROWTH = 25%
) 
LOG ON (
    NAME = N'BSTU_log', 
    FILENAME = N'D:\BD\BSTU_log.ldf', 
    SIZE = 10240Kb, 
    MAXSIZE = 2048Gb, 
    FILEGROWTH = 10%
);
```

**Разбор параметров файла:** 
* `NAME` — логическое имя файла внутри сервера. 
* `FILENAME` — физический путь к файлу на жестком диске. 
* `SIZE` — начальный выделенный размер. 
* `MAXSIZE` — максимальный размер (можно ограничить в Gb/Kb или указать `UNLIMITED`). 
* `FILEGROWTH` — шаг автоматического расширения файла (в мегабайтах/килобайтах или процентах).

**Категории команд языка T-SQL** 

Все команды T-SQL логически делятся на несколько групп: 

* **DDL (Data Definition Language)** — язык определения данных.  Отвечает за структуру: 
  - `CREATE` — создание объектов (БД, таблиц). 
  - `ALTER` — изменение структуры объектов. 
  - `DROP` — удаление объектов. 

* **DML (Data Manipulation Language)** — язык манипулирования данными.  Отвечает за сами записи: 
  - `SELECT` — выборка (чтение) данных из таблиц. 
  - `INSERT` — вставка новых строк. 
  - `UPDATE` — обновление (изменение) существующих данных. 
  - `DELETE` — удаление строк. 

* **DCL (Data Control Language)** — язык управления доступом: 
  - `GRANT` — выдача разрешений. 
  - `REVOKE` — отзыв выданных разрешений. 
  - `DENY` — явный запрет на действия. 

## Представления (VIEW) ## 

* Представления (Views) представляют собой виртуальные таблицы.  В отличии от обычных таблиц, они содержат запросы, которые динамически извлекают данные. 
* Представления дают ряд преимуществ: упрощают комплексные SQL-операции.  Они защищают данные, так как могут дать доступ лишь к части таблицы.  Также они позволяют возвращать отформатированные значения в удобной форме. 
* Типы представлений в SQL Server: индексированные, секционированные, системные и модифицируемые. 

**Модифицируемые представления:** 
* Если изменить данные в модифицируемом представлении (через `UPDATE`, `INSERT` или `DELETE`), они изменятся и в базовых таблицах, хранящих эти данные. 
* Критерии модифицируемого представления: 
  - Должно выводиться в одну базовую таблицу.  
  - Не должно иметь агрегатных функций. 
  - Не должно содержать `DISTINCT`, `GROUP BY` или `HAVING`. 
  - Не должно использовать подзапросы и константы/выражения в полях вывода. 
  - Для `INSERT` должно содержать все поля основной таблицы, имеющие ограничение `NOT NULL`. 

**Синтаксис VIEW:** 
* Создание: `CREATE VIEW название_представления AS выражение_SELECT`. 
* Изменение: `ALTER VIEW название_представления AS выражение_SELECT`. 
* Удаление: `DROP VIEW название_представления`.  При удалении таблиц также следует удалять и связанные с ними представления.

## Оконные функции (Продвинутый уровень) ## 

* Задачи, которые решаются окнами: ранжирование, сравнение со смещением (соседние элементы), агрегация и скользящие агрегаты в динамике. 
* В MS SQL Server и Oracle оконный запрос пишется внутри инструкции `OVER` (например, `OVER (PARTITION BY ... ORDER BY ...)`). 
* `PARTITION BY` указывает, как следует разбить окно на независимые секции. 
* `ORDER BY` внутри окна задает сортировку строк внутри секции. 

**Функции ранжирования:** 
* `row_number()` — возвращает последовательный порядковый номер строки. 
* `dense_rank()` — возвращает ранг строки без пропусков (например, 1, 2, 2, 3). 
* `rank()` — возвращает ранг строки с пропусками (например, 1, 2, 2, 4). 
* `ntile(n)` — разбивает все строки на `n` групп одинакового (по возможности) размера и возвращает номер группы для строки.

## Хранимые процедуры и функции ## 

* Хранимые процедуры — это подпрограммы (набор команд SQL), которые компилируются, хранятся на сервере и могут быть многократно вызваны. 
* Преимущества: повторное использование кода, сокращение сетевого трафика, инкапсуляция логики, безопасность целостности данных. 
* Для вызова процедуры используется функция `CALL имя_процедуры([параметры])`. 

**Параметры хранимых процедур:** 
* `IN` — данные передаются строго внутрь процедуры (если параметр изменить внутри, новое значение не сохранится на выходе).  Это значение по умолчанию. 
* `OUT` — данные передаются строго из процедуры наружу (начальное значение игнорируется). 
* `INOUT` — значение принимается внутри процедуры и сохраняет изменения по выходу из нее. 

**Отличия Функции от Процедуры:** 
* Функция вызывается непосредственно (без `CALL`) и возвращает ровно одно значение (`RETURNS type`), которое подставляется в место вызова. 
* В функциях нельзя использовать слова `IN`, `OUT`, `INOUT` — все параметры по умолчанию являются входными. 

**Готовые инструкции (Prepared Statements):** 
* Позволяют создать SQL-инструкцию в формате строки и безопасно вставить туда переменные (вместо `?`). 
* Синтаксис: `PREPARE имя_инструкции FROM 'запрос'`, затем `EXECUTE имя_инструкции USING @переменная`. 
* Удаление: `DEALLOCATE PREPARE имя_инструкции`. 

**Переменные:** 
* **Пользовательские переменные:** обозначаются через `@` (например, `@var`).  Создаются в момент присвоения им значения (например, `SET @var=123;`) и живут до завершения сеанса (соединения). 
* **Локальные переменные хранимого кода:** живут только внутри процедуры/функции.  Объявляются через `DECLARE имя тип_данных [DEFAULT значение]` и требуют указания типа. 
* Чтобы поместить значение из таблицы в переменную, используется: `SELECT столбец INTO переменная FROM таблица`. 

**Управление потоком данных (Циклы и условия):** 
* Тело процедуры оборачивается в составной оператор `BEGIN ... END`. 
* `IF условие THEN ... ELSEIF ... ELSE ... END IF` — классическое ветвление. 
* `CASE` — оператор множественного выбора (`CASE WHEN условие THEN ... END CASE`). 
* `WHILE условие DO ... END WHILE` — цикл с предусловием. 
* `REPEAT ... UNTIL условие END REPEAT` — цикл с постусловием. 
* `LOOP ... END LOOP` — бесконечный цикл. 
* `LEAVE метка` — досрочный выход из цикла (аналог break). 
* `ITERATE метка` — выполнить цикл снова (аналог continue). 

**Курсоры и Обработчики ошибок:** 
* Курсоры — это указатели на ресурс выборки, позволяющие построчно обрабатывать результаты запроса.  Существуют только внутри процедур/функций, работают только на чтение. 
* Использование курсора: `DECLARE имя CURSOR FOR запрос`, затем `OPEN имя`, потом `FETCH имя INTO переменные` и в конце `CLOSE имя`. 
* Обработчики ошибок: перехватывают ошибки выполнения.  Синтаксис: `DECLARE {CONTINUE | EXIT} HANDLER FOR код_ошибки действия`.  Позволяют продолжить (`CONTINUE`) или прервать (`EXIT`) выполнение кода при ошибке (например, когда курсор доходит до конца — `SQLSTATE '02000'`).
